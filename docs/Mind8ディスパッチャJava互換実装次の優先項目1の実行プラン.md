# Mind8ディスパッチャ Java互換実装 次の優先項目1の実行プラン

## 目的

通常ユーザーカーネルのC関数番号表とJava版の関数テーブル登録を番号・関数名・処理内容の三段階で照合する。C#版で確定した差分と未実装状況を参考にしつつ、Java版の実際の登録を独立に確認し、以降の実装とテストが依拠する対応表を作る。

## 前提と対象

- 現状のJava版は `Dispatcher.setupFunctions()` が空の枠であり、登録済み関数はない。C#版の179登録をJava版の実装済み件数として扱わない。
- C版基準: `mind8kernel/c_words.tbl`、必要に応じて `c_words.def`、対象カーネルの選択設定、該当C関数。
- Java版: `src/mind8dispacher/Dispatcher.java` の関数テーブルと各ハンドラー。
- 対象カーネルは通常ユーザーカーネルに固定する。別カーネルとの差は本項目の範囲外として記録する。
- 成果物: Java側の対応表、再実行可能なテーブル検査、未登録・誤割当ての実装状況記録。

## 作業手順

1. C#完了レポートを基準情報として確認し、通常ユーザーカーネルのC表が `0x0010`～`0x02F6` の743番号であること、C#照合で確認されたエイリアス11組と `0x0061` の修正根拠を引き継ぐ。実際に利用する `c_words.tbl` のパス、版、終端の扱いも記録する。
2. `c_words.tbl` を読み、予約番号・関数番号・関数名・テーブル終端を含むC側一覧を作る。数値は16進表記とし、コメントやエイリアス表記を実エントリーと混同しない。
3. Java関数テーブルの設計を固定する。C番号から配列添字への変換、配列長、予約範囲、未登録要素の扱いを明記し、登録メソッドの名前とC表の名前を対応付ける。番号を詰め直した独自表は作らない。
4. すべてのJava登録を抽出してC表と番号をキーに比較し、「一致」「CにありJava未登録」「Javaにのみ登録」「同番号で別関数」「重複番号」「意図した同一関数エイリアス」に分類する。
5. 別関数名・重複・エイリアス候補について、C表だけで決めず該当C関数とJavaハンドラーの意味を確認する。C#レポートで修正された `0x0061` もJava版の独立した確認対象とし、C#の修正を根拠にJavaの正しさを推定しない。
6. 差分表に、実装有無、根拠、互換性影響、対応方針、未確定事項を記録する。未登録番号は意図的な未対応として明示し、null呼出しや無言の無視に依存させない。
7. テーブル検査を再実行できる形にする。プロジェクトにテスト基盤がない場合は、依存を増やす前に既存のビルド方法と整合する小さな検査プログラムまたはスクリプトを選び、検査対象と使い方を記録する。

## 検証と完了条件

- C側の選択した全エントリーとJava側の全登録が比較結果に現れ、範囲外登録・重複・名前の不一致が分類されている。
- 関数番号を配列添字へ写す規則とテーブル上限が、C版の番号体系と一致する。
- エイリアスはC版の根拠とJava側の同一処理を確認してから許容し、番号が同じという理由だけで互換と判断しない。
- 未登録番号を実行した場合の失敗動作が明示され、例外または検査可能なエラーとなる。
- テーブル検査が再実行可能で、差分の一覧と修正・保留方針がJava実装状況資料に記録されている。

## 依存・注意点

項目4の比較テストがこの対応表を検証オラクルとして使う。C#の完了レポートはC版との比較結果およびC#側の実装数に関する資料であり、Java版の登録完了を意味しない。関数の意味と番号が確定するまでは登録先だけを一括変更しない。
