# Mind8ディスパッチャ Java互換実装 次の優先項目2の実行プラン

## 目的

C版 `openMcodeFile()`、`readMcodeInfoTable()`、エンディアン判定・変換および `setupForDispatch()` の契約をJava版に反映し、MCOの解決・検査・読込みを命令実行前に完了させる。不正または対象外のMCOを安全かつ診断可能な形で拒否する。

## 前提と対象

- Java版 `Dispatcher.setupForDispatch(String[])` は現在未実装であり、ローダーはこれから設計・実装する。
- C#完了レポートで通常ユーザーカーネルの基準として確認された値はVersion 8、Runtime 10、Serial 42、`BigEndianMcodeBit` `0x20`、`EndianInfoRatio` 8。Java実装前に、C側の対象設定とMCOレイアウトを再確認し、設定値を出典付きで固定する。
- C版: `kermain.c` のMCO解決・読込み・情報検査・スワップ処理、関連する `kernel.def`、`serialno*.def`、`runtno*.c`。
- Java版: `Dispatcher.java`、後続で必要となるMCO情報・ロード結果の型、および `Main.java` の引数処理。
- 成果物: ファイル解決規則、検証済みロード結果、正常系・異常系ローダーテスト。

## 作業手順

1. C版の対象カーネルを固定し、MCO末尾32バイトの各フィールド、`MC`マーク、MAIN情報、Version、Runtime、Serial、エンディアンフラグ、Mコード・LOC・データ・スタックの各サイズと読込み順を表にする。C構造体のパディングや整数幅を含め、ソースと実データから確認する。
2. C版のファイル名規則とJavaアプリケーションで必要な範囲を決める。引数がない場合の既定名、`.mco`補完、大文字小文字、相対パス、存在しないファイルの扱いを定義する。C版のCGI等の環境別検索先を移植しない場合は対象外と記録する。
3. 読込みを「名前解決」「ファイルサイズ・完全読込み確認」「末尾情報デコード」「全フィールド検査」「ペイロード境界検査」「バイト順補正」「Mコード・LOC構築」に分ける。検査完了前に部分状態をDispatcherへ公開しない。
4. Java 20の標準APIでバイト順を明示する。`ByteBuffer.order(...)` または `java.nio.ByteOrder` を使い、ホスト環境に依存する解釈を避ける。符号なし16/32ビット値は必要に応じて `Short.toUnsignedInt` / `Integer.toUnsignedLong` を使い、ファイル長や添字との比較で符号拡張・オーバーフローを避ける。
5. 異なるエンディアンのMCOでは、C版のEDI表に基づく選択的なMコード変換とLOCの32ビット値変換を行う。すべてのワードを一律反転する実装に置き換えず、EDI比率・ビット割当て・テーブル境界をCソースで確認する。
6. `MC`、Version、Runtime、Serial、MAIN、各領域サイズ、ファイル境界、完全読込み、EDI表の必要範囲を検査する。負の長さ、巨大なサイズ、整数加算オーバーフロー、切詰め入力に対して配列確保前に拒否する。
7. 入力不備、互換条件不一致、I/O失敗を区別する例外または結果契約を定め、呼出し側でファイル名・項目・理由が追跡できる診断を出す。生の例外を利用者向けエラーとして漏らさない。
8. 合成MCO fixtureを用意し、正しいリトル／ビッグエンディアン、拡張子規則、各ヘッダーフィールド異常、短いファイル、ペイロード・EDI切詰め、サイズ境界を検証する。同梱MCOはメタデータを確認し、対象カーネルと不一致なら正常系fixtureとして誤用しない。

## 検証と完了条件

- 通常ユーザーカーネル用MCOの `MC`、Version 8、Runtime 10、Serial 42、MAINおよびサイズ・境界条件をC版と同じ規則で検査する。
- 両エンディアンのfixtureで、MCO情報、Mコード、LOCの論理値が一致し、EDI変換に必要な入力が不足する場合は安全に拒否する。
- `.mco`拡張子の省略・大文字小文字・相対パス・不在ファイルの動作が定義されテストされる。
- 短いファイル、サイズ不整合、非対応識別値、異常なMAIN、オーバーフロー候補、ペイロード・EDI切詰めを命令実行前に拒否する。
- 成功時のみ初期化済みポインター群をDispatcherへ渡し、失敗時に部分初期化状態を実行へ進めない。

## 依存・注意点

項目1で選んだカーネル表と同じカーネル設定を使用する。Serial 42などの値はC#資料の対象構成で確認された値であり、別カーネルに無条件で適用しない。MCOの正確なフィールド配置はCソースおよびファイル形式の実データから確定し、推測で固定しない。
